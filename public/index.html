Your deposit,
held by no one.

It sits in a NEAR account with no keys, running code pinned by hash. Nobody can move it by hand. The tenant gets it back by default, unless the landlord files a claim in time.

Try it in two minutes

No wallet and no sign-up. This opens a real vault on NEAR testnet with short timers (2 minutes), and lets you switch between landlord, tenant and arbiters to play every step. It uses shared throwaway test accounts whose keys are public, so nothing here is private or valuable.

    In 30 seconds
    
    
    Today a landlord holds the caution deposit and the tenant hopes to get it back. Here the deposit sits in a NEAR account with no access keys. Its code is referenced by hash from a global contract, so no publisher can swap it. Neither side can take the money out by hand: only the contract rules move it.
    
    
      
      
    1. Both sides agree the lease terms and a move-in condition report. Only a salted hash of them goes into the vault. No names, addresses or photos are on chain.
      2. 
      
    2. The deposit is paid in, up to a cap.
      3. 
      
    3. The tenant declares handover. The landlord then has a fixed window to file one claim.
      4. 
      
    4. No claim: anyone can trigger the refund to the tenant. Claim: only the claimed amount stays locked and the rest goes back to the tenant at once.
      5. 
      
    5. The tenant can put one reply on the record. An arbiter named in the lease splits the locked amount and records a hash of the reasons. A second arbiter can step in if the first stays silent. Payouts always sum to exactly the amount held.
      6. 
      
    6. If neither arbiter rules by the deadline (two arbiter waits after the claim), the claim lapses and the tenant is refunded. Silence never locks the money.
      7. 
      
    7. The deposit can be held in a dollar stablecoin instead of NEAR, so it keeps its value while the lease runs.
      8. 
    
    
    
    Why NEAR, honestly
    
    
    Refund-by-default escrow can be written on other chains, and other projects have. What NEAR adds here:
    
    
      
      
    • Keyless is a checkable property. The vault is a deterministic account created from a code hash and its terms. Anyone can confirm with one RPC call that it has zero keys and which code it runs. The Vaults tab does exactly that.
      • 
      
    • One published copy of the code. Each vault only references the global contract by hash, so creating a vault is cheap after the one-time publish.
      • 
      
    • Named nested accounts fit buildings and units: unit-4b.building.testnet.
      • 
    
    
    
    What this does not do
    
    
      
      
    • This deployment runs on NEAR testnet. The money is test tokens. Before real money: an independent audit of the contract and a legal review, neither done.
      • 
      
    • It does not replace a court. It is a private contract between the parties. We have not checked how Nigerian courts would treat it.
      • 
      
    • Disputes still need a human arbiter, and an arbiter can be wrong. Who the arbiters are, and how they are chosen and paid, is something the landlord and tenant agree outside the chain. The vault only enforces that a ruling splits the locked amount, records the reasons' hash, and cannot be stalled forever.
      • 
      
    • Landlords must choose to use it. We have not verified that any would.
      • 
      
    • A vault in NEAR moves with NEAR's price. A vault in a dollar stablecoin avoids that, and protects against naira inflation only to the extent that dollars hold their value against the naira. On testnet the stablecoin is a test token (tUSD) with no value. There is no naira token or naira on-ramp, and no mainnet stablecoin account has been configured yet.
      • 
      
    • Paying in from other chains through NEAR Intents is not built: Intents has no testnet.
      • 
      
    • Wallets cannot create keyless vaults yet, so opening one is signed by a small key in your browser. It only pays the fee and has no power over the vault. Paying in, claims and rulings are signed by your wallet.
